# Go 房间服务

本目录是 `io.dbx.doudizhu` 的 DBX Protocol v1 sidecar。`main.go` 保留 stdout 给 JSONL RPC，日志只写 stderr。Go 1.22 及以上；根项目的打包命令将本程序编译到插件 `bin/`。

## 本地开发

```sh
go test -race ./...
go vet ./...
go build -o ../bin/dbx-doudizhu.exe .
```

运行在 DBX 中时，身份和偏好存放于 `DBX_PLUGIN_DATA_DIR/identity.json`。每台机器第一次运行生成 Ed25519 身份；昵称不作为身份凭据。同机多客户端验收时，给每个 sidecar 设置不同的数据目录。独立运行可使用 stdin/stdout 的同一协议，未设数据目录时回退到用户配置目录下的 `dbx-doudizhu`。

## 网络和生命周期

- 房主启动 TLS 1.3 TCP 服务，系统分配空闲端口。其他玩家的 Go sidecar 通过长连接发送 JSONL 消息，浏览器没有网络凭据、密码哈希或对手手牌。
- `_dbxddz._tcp.local.` mDNS 广播房间标识和房主公钥摘要，局域网发现持续 1.5 秒，再通过 TLS 查询当前人数与阶段并验证可达地址。发现房间包含多个网卡地址时，并发探测选出可达地址；加入时仍有逐地址回退，每个地址限时 1.5 秒，避免首个 VPN 地址不可达就阻断加入。多播不可用时仍可输入房主 `IP:端口`。Windows 首次建房可能显示系统防火墙的入站连接提示。
- 房间密码仅在主机保存 bcrypt 哈希，通过 TLS 发送的密码用于首次加入。每个连接先完成随机挑战签名；重连凭据绑定该签名身份。每 IP 一分钟五次失败后暂时拒绝新认证。
- TLS 证书公钥与发现记录核对；手动地址使用首次信任（TOFU）并持久保存该地址的主机身份。它适用于可信局域网，不是依赖公共 CA 的互联网身份系统。
- 每个房间只有主机执行规则和结算；每个玩家收到独立快照。RPC 发送动作编号和可选版本号，防止重复执行、过期出牌。事件可能在宿主中丢失，UI 定期获取完整快照恢复状态。
- 断线后客户端自动重连最多 60 秒；房间保留身份、席位和手牌，并启用托管。非对局中的离线席位超过 60 秒释放；进行中的离线玩家由托管完成。旧连接的代际标识立即失效。
- 关闭工作台 UI 不离房；Go 继续心跳和托管，重新打开用 `room.snapshot` 恢复。只有显式“离开房间”结束本机会话。房主关闭房间或退出 DBX 后服务结束，没有主机迁移；未完成牌局不结算。
- 欢乐豆是房间内存账本。同一身份离开再加入不会补豆；全体当前在席玩家同意后才重置整个房间账本。新房间重新初始化，房主进程停止后房间终止。
- 礼物、快捷语不扣豆，服务端执行 3 秒冷却和动作去重；它们不进入重连重放。

## 测试范围

`internal/app/app_test.go` 使用三个独立 App 和真实 TLS 回环连接验证建房、密码、个人手牌隔离、身份与 token 绑定、断线重连、关房不误结算，以及房间账本、旧会话失效、社交限频与重复动作。mDNS 测试在系统多播可用时进行实际广播与扫描；不支持多播的 CI 会明确跳过该项。不同电脑上的系统防火墙、无线 AP 隔离仍需现场联机验收。

`third_party/dbx-plugin-sdk` 是 DBX Go SDK 的源码副本，附带原 Apache-2.0 许可证；仅通过相对 `replace` 使用，不依赖开发电脑上的 DBX 路径。规则包由 `internal/game` 提供，其第三方许可证见该目录。
